# Anti-Slop Audit 002 (UI focus)

Mode: AFTER. This report audits the visual/UI layer only; functional rules were covered by [Audit 001](audit-001-2026-10-02.md) and its follow-up. Nothing was modified for this audit.

Scope: public pages (`pages/index.tsx`), sections, shared components, `styles/globals.css`, content/project data defaults, and live rendering via `npm run dev` at localhost:3000 (dark and light themes, desktop viewport; mobile was not re-tested in this audit but layout rules were re-verified against Audit 001's mobile evidence).

Design Read: personal portfolio for employers, recruiters, and creative clients; the existing "signal & depth" industrial-electronics language. Dials stand as declared in Audit 001: ENERGY 3 / RHYTHM 3 / MOTION 3.

## Findings

1. **[HIGH] Contact form error text fails WCAG AA in light mode (R-25).** [components/sections/Contact.tsx](../components/sections/Contact.tsx#L236) hard-codes `#f87171` for the feedback line. On the light theme surface (`--bg` `#eef3ea`) the measured ratio is about 2.5:1, below 4.5:1 for small text. The same red passes on the admin dark surface (about 5.5:1), so the token is only broken on the public light theme.

2. **[MEDIUM] The scroll rail shows fabricated instrumentation numbers (R-17, R-31).** [components/ScrollRail.tsx](../components/ScrollRail.tsx#L54) prints `0000 0900 1800 2700 3600` at fixed positions of a 0-100% progress rail. The numbers correspond to nothing: they are `index * 900` literals that neither match scroll position (the marker maps 4%-92% over the whole page) nor any real unit. This is status-language used as decoration. The trailing `'</>'` glyph on the same rail (line 70-72) is also decoration with no meaning.

3. **[MEDIUM] Em dash in the default certification description (R-02).** [data/content.ts](../data/content.ts#L205) contains `(2026) \u2014 Kompeten. ...`. The live Firestore copy already uses an updated description without it (verified in-browser), so only the offline/fallback default renders it; the default is also the one walked through by audits and seeding. Fix in source; the en dash characters used for date ranges elsewhere are within the rule.

4. **[MEDIUM] Irrelevant icon plus mixed icon strategy in the capability grid (R-04).** [data/content.ts](../data/content.ts#L167) assigns the `travel_explore` glyph (magnifier over a globe) to "Three.js, WebRTC & Socket.IO"; it communicates nothing about 3D or real-time networking, while neighbours in the same list use real devicon logos. Either pick a relevant glyph or show none; at minimum do not mix an unrelated metaphor into a list that otherwise uses logos.

5. **[MEDIUM] Every button and chip shares one shape register: stadium pill + uppercase + wide tracking + extrabold (R-11, R-06).** Hero CTAs ([Hero.tsx](../components/sections/Hero.tsx#L76-L98)), the nav Resume button ([TopNav.tsx](../components/TopNav.tsx#L115)), the contact form submit ([Contact.tsx](../components/sections/Contact.tsx#L228)), the project tabs, and the card category chips all use `rounded-full` + `uppercase` + `tracking-wide` + `font-extrabold`. The mono uppercase labels have a written reason (the "signal & depth" motif); button typography does not, and the uniform pill shape flattens the primary/secondary hierarchy. Note this re-opens Audit 001's R-11 PASS at the button level: radius varies between cards and inputs, but every control is a stadium.

6. **[MEDIUM] Declared RHYTHM 3 / MOTION 3 versus uniform execution (R-05, R-19).** Every section uses the same `max-w-7xl / px-5 md:px-16 / py-24 md:py-32` container, the same `whileInView { opacity, y: 24 }` fade-up on its items, the same `gap-6` grid rhythm, and the same `surface-card` treatment. Sections differ in internal composition (tabs grid, numbered rows, flip cards, marquee), which keeps this at MEDIUM rather than HIGH, but spacing and scroll choreography are identical everywhere, which contradicts the declared RHYTHM 3 dial.

7. **[LOW] Hero badge cards duplicate the Capabilities section and are four identical cards (R-14, C-3).** [Hero.tsx](../components/sections/Hero.tsx#L146-L166) renders ESP32/Arduino, PID/Fuzzy, PLC/SCADA, and Fotografi/Desain as the literal first four rows of `CAPABILITIES` ([content.ts](../data/content.ts#L124-L196)). Audit 001 justified the equal hierarchy, but the duplication plus equal-card grid is worth revisiting now that the full Capabilities section exists below.

8. **[LOW] Single typographic weight register (R-06, R-31).** `font-extrabold` is used for h1, h2, h3, card titles, button labels, stat values, and badge values. With every element at 800, weight no longer signals hierarchy; one or two levels down (700 for card titles, 500-600 for controls) would restore the size-weight contrast the display font was chosen for.

9. **[LOW] Unreachable empty state in StatsBar (C-2 hygiene).** [components/sections/StatsBar.tsx](../components/sections/StatsBar.tsx#L8) returns `null` for an empty list, so the `role="status"` block at lines 28-32 can never render. Either gate on a loading state or delete the dead branch.

## Non-findings (re-checked, still pass)

- The fluid shader background, grain overlay, custom cursor, and intro curtain each keep a stated purpose and the Audit 001 dose caps hold (R-01, R-07, R-10, R-13).
- Contact form placeholders are honest ("Nama lengkap Anda", "email@contoh.com"); social links are real handles; certification badges carry real labels; project photos are real or explicitly labelled (R-23, R-36, R-38).
- Theme toggle works in both themes; nav items map to real sections; empty states render for every CMS-driven list (R-24, R-26, R-27, R-34).

## Verification evidence

- `npm run dev` served `/` (HTTP 200, Next.js 15.5.23) and the site was screenshotted section by section in dark and light themes.
- Live DOM checks: hero text, buttons, project cards, certification text, and social links render from Firestore with the local fallback intact.
- Error-color ratio measured against both theme surfaces as reported in finding 1.
- No files were modified; theme state was restored to dark after inspection.

## Proposed improvements (optional, not rule violations)

The owner asked for a more attractive UI overall. These proposals were NOT applied and need approval, possibly against Audit 001's approved decisions:

- **P-1: Tighten the hero.** Cut the 6-sentence bio to 2 sentences in the hero (the full text already exists in Pengalaman/Lisensi), letting the name, CTAs, and photo breathe on the first screen.
- **P-2: A second identity motif.** Beyond mono labels, add one consistent "signal" gesture (e.g., a tick-marked section header rule or a thin waveform divider) so sections feel authored, giving the RHYTHM dial something concrete to vary.
- **P-3: Vary section spacing and composition.** Alternate tight and airy blocks instead of uniform `py-24/py-32`; give Arsip Karya a full-bleed edge treatment; restructure Lisensi into an asymmetric two-column layout to match the two certificates.
- **P-4: Button hierarchy.** Keep the stadium for the single primary CTA; drop uppercase/tracking on secondary buttons and chips; vary radius by control type.
- **P-5: Weight scale.** Introduce 700 for card titles and 500-600 for controls so 800 belongs to display headings only.
- **P-6: Micro-interactions with purpose.** Replace the icon-rotate bump with a staggered tag reveal on project card hover; make the scroll rail show the real current section instead of fake numbers.
