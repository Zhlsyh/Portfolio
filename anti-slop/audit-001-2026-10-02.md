# Anti-Slop Audit 001

Mode: AFTER. This report records the initial audit. Findings 1-13 were approved for repair; finding 14 was intentionally left unchanged because the Google Drive destinations are deliberate.

Scope: portfolio pages, shared components, admin CMS, content data, project data, styles, and setup documentation.

Design Read: personal portfolio for employers and engineering/creative clients, in the existing industrial-electronics "signal & depth" language. Dials: ENERGY 3 / RHYTHM 3 / MOTION 3.

Decision notes: dark evergreen and mint follow the existing signal motif; display type gives the name a strong first-screen hierarchy while the sans body font supports longer project descriptions; section layouts change to fit chronology, work samples, skills, credentials, and contact; motion guides entry and section transitions, but must respect reduced-motion preferences.

## Findings

1. **[HIGH] Resume downloads point to missing files (R-26).** [components/ResumeModal.tsx](../components/ResumeModal.tsx#L12) links three filenames that do not exist in `public/`; the available PDFs use different names, so each visible download returns a missing resource.

2. **[HIGH] The hero image is clipped at 320px (R-03).** [components/sections/Hero.tsx](../components/sections/Hero.tsx#L22) clips overflow around a 334px image frame at a 320px viewport; the frame extends 12px beyond the left edge and the document has 4px of horizontal overflow.

3. **[HIGH] Secondary text fails WCAG AA contrast (R-25).** [styles/globals.css](../styles/globals.css#L18) defines `--text-faint` at 3.79:1 on the dark background and 2.72:1 on the light background; both are below 4.5:1 for the small labels and supporting text that use this token.

4. **[HIGH] Keyboard focus escapes the full-screen menu (R-32).** [components/FullScreenMenu.tsx](../components/FullScreenMenu.tsx#L89) and [components/OrgFlipCard.tsx](../components/OrgFlipCard.tsx#L22) use clickable `div` elements; during browser testing, Tab from the open menu moved to the hero CTA behind it. The resume and project overlays also lack dialog semantics and focus containment.

5. **[HIGH] Admin inputs have no programmatic labels (R-32).** [components/admin/FormControls.tsx](../components/admin/FormControls.tsx#L3) renders a label without `htmlFor` or a wrapped control, and [components/admin/LoginForm.tsx](../components/admin/LoginForm.tsx#L56) does the same; browser inspection found zero associated labels on both login inputs.

6. **[HIGH] Firebase and save failures have no visible error state (R-27).** [context/SiteDataContext.tsx](../context/SiteDataContext.tsx#L39) marks failed snapshots as loaded without recording the error, while multiple admin editors only clear their saving state in `finally`; visitors can see fallback content and editors can lose a failed save without actionable feedback.

7. **[HIGH] The Hero CMS name fields do not control the displayed name (R-26).** [components/admin/HeroEditor.tsx](../components/admin/HeroEditor.tsx#L44) saves `title1` and `title2`, but [components/sections/Hero.tsx](../components/sections/Hero.tsx#L48) renders hard-coded name strings instead.

8. **[HIGH] The navigation editor can save destinations that do not exist (R-24).** [components/admin/NavEditor.tsx](../components/admin/NavEditor.tsx#L39) accepts any `href`; [components/TopNav.tsx](../components/TopNav.tsx#L39) silently does nothing when that selector has no matching section.

9. **[HIGH] Firestore write rules contradict the single-admin security claim (R-36, C-5).** [ADMIN_SETUP.md](../ADMIN_SETUP.md#L41) says only the admin may write, but the rules at [ADMIN_SETUP.md](../ADMIN_SETUP.md#L44) and [ADMIN_SETUP.md](../ADMIN_SETUP.md#L48) allow writes from every authenticated UID, with no admin allowlist or claim check.

10. **[HIGH] Stock photography is presented as project evidence (R-38).** [data/projects.ts](../data/projects.ts#L233) and other project records use Unsplash images as project covers without identifying them as illustrative placeholders; a visitor cannot distinguish stock imagery from documentation of the named work.

11. **[HIGH] Reset does not remove projects absent from the defaults (R-26, C-2).** [lib/adminData.ts](../lib/adminData.ts#L37) only writes default documents, while [components/admin/SeedPanel.tsx](../components/admin/SeedPanel.tsx#L17) promises to overwrite all project and content data; CMS-created project documents remain after reset.

12. **[HIGH] README describes an unimplemented contact widget and unsupported performance claim (R-36, R-38).** [README.md](../README.md#L23) calls the animations high-performance without evidence, and [README.md](../README.md#L29) describes a floating quick-contact FAB that is not present in the project components.

13. **[MEDIUM] Reduced-motion preferences do not disable the intro and other page choreography (R-19).** [components/IntroScreen.tsx](../components/IntroScreen.tsx#L21) still blocks the page for its timed animation, and the global media rule in [styles/globals.css](../styles/globals.css#L79) only changes the cursor; not all motion components respond to the preference.

14. **[LOW] Project link labels do not identify the destination (R-15).** [components/ProjectModal.tsx](../components/ProjectModal.tsx#L115) labels every external destination "Kunjungi Tautan", including demos and documentation; several records in [data/projects.ts](../data/projects.ts#L236) point only to the generic Google Drive homepage.

## Verification

- `npm run build`: PASS. Next.js compiled, type-checked, and exported the site.
- Browser checks: theme toggle changed modes; mobile menu opened and Escape closed it; resume and project modals opened and closed with Escape; project category tabs changed; an empty contact form focused the first required field; default in-page links had matching targets.
- Responsive checks: no document overflow at 360px, 375px, 390px, 768px, or 1024px; the 320px hero clipping is finding 2.
- `/admin` rendered the login screen. I did not authenticate or exercise destructive CMS controls without credentials, so the admin click-through is incomplete.
- The browser environment blocked Firestore streaming and some Googleusercontent images. Those network failures are not treated as confirmed application defects in this report.
- This is the initial-state record. See [the follow-up report](audit-001-follow-up-2026-10-02.md) for approved fixes and post-change verification.
